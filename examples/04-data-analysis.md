# 예제 4. 데이터 분석: 계산은 코드로, 가정은 드러나게

> 언어 모델은 "말"을 생성하는 도구라서 **암산이 약합니다.** 숫자를 다룰 때는 반드시 코드를 실행하게 하세요.
> Karpathy도 "How I use LLMs"(2025)에서 계산이나 데이터 작업에는 코드 실행 도구를 쓰라고 권합니다.

---

## ❌ 흔한 방식

```text
(엑셀 표를 텍스트로 붙여넣고)
지역별 평균 매출이랑 성장률 알려줘.
```

- 모델이 머릿속으로 계산해서 **숫자가 틀릴 수 있습니다.**
- 빈칸, 중복 행, 단위(원/천원) 같은 데이터 문제를 **조용히 무시**합니다.
- "성장률"의 정의(전년 대비? 전월 대비?)를 **멋대로 정합니다** (오해).

---

## ✅ 개선한 프롬프트

```xml
<context>
첨부한 sales_2026.csv는 2025~2026년 월별·지역별 매출 데이터야. (단위: 천원)
분기 보고서에 들어갈 표를 만들려고 해.
</context>

<task>
0. 분석 전에 데이터를 점검하고 보고해줘: 행/열 수, 결측치, 중복 행, 이상치(평균 ±3σ 밖), 단위 이상.
   문제가 있으면 어떻게 처리할지 제안만 하고, 내 확인을 받은 뒤 진행해줘.
1. 지역별 2026년 1~3분기 평균 월매출
2. 지역별 성장률 = (2026년 1~3분기 합계 / 2025년 1~3분기 합계) - 1
3. 성장률 상위 3개 지역과 하위 3개 지역
</task>

<constraints>
- 모든 계산은 파이썬 코드를 실행해서 해. 사용한 코드도 보여줘.
- 내가 정의하지 않은 지표를 쓸 때는 정의를 먼저 밝혀줘.
- 해석(왜 올랐는지)은 데이터만으로 알 수 없으면 "데이터로는 알 수 없음"이라고 써줘.
</constraints>

<format>
1) 데이터 점검 결과 (불릿)
2) 결과 표 (지역 | 평균 월매출 | 성장률 | 순위)
3) 눈에 띄는 점 3가지 (각 1줄, 근거 숫자 포함)
4) 사용한 코드
</format>
```

---

## 왜 이렇게 쓰는가

| 장치 | 막는 문제 |
|---|---|
| "코드를 실행해서 계산" | 계산 오류 (지어냄의 한 형태) |
| 0단계 데이터 점검 + 확인받기 | 결측치·중복 무시 (누락) |
| 성장률 정의를 직접 씀 | 지표 정의 착각 (오해) |
| "데이터로는 알 수 없음" 허용 | 그럴듯한 원인 지어내기 (지어냄) |
| 코드 공개 | 사람이 검증 가능 |

---

## 사람이 하는 검증

- [ ] 표의 숫자 1~2개를 엑셀에서 직접 계산해 맞춰 봤다
- [ ] 코드에서 필터 조건(기간, 지역)이 내 의도와 같은지 읽어 봤다
- [ ] "눈에 띄는 점"의 근거 숫자가 표에 실제로 있는지 확인했다

> 💡 개인정보나 회사 기밀이 들어 있는 데이터는 회사가 허용한 AI 서비스에만 올리세요. 자세한 내용은 [docs/09-security-privacy.md](../docs/09-security-privacy.md)를 참고하세요.
