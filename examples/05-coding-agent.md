# 예제 5. 코딩 에이전트로 버그 고치기: 탐색 → 계획 → 테스트 → 구현 → 검증

> Claude Code, Codex 같은 코딩 에이전트는 파일을 읽고, 명령을 실행하고, 코드를 고칩니다.
> 강력한 만큼 **방향이 틀리면 빠르게 엉뚱한 곳으로 갑니다.** 핵심은 짧은 단계로 나누고, 단계마다 **에이전트가 스스로 확인할 수단**을 주는 것입니다.

**상황:** 쇼핑몰 장바구니에서 할인 쿠폰을 두 번 적용하면 총액이 음수가 되는 버그가 있다.

---

## 1단계. 탐색 (코드 수정 금지)

```text
아직 코드는 수정하지 마.
장바구니 총액 계산과 쿠폰 적용 로직이 어디 있는지 찾아서 흐름을 요약해줘.
관련 테스트 파일이 있는지도 알려줘.
```

> 계획 모드(Plan mode)가 있는 도구라면 계획 모드에서 실행하세요.

## 2단계. 계획 (사람이 승인)

```text
쿠폰 중복 적용 버그를 고칠 계획을 세워줘.
- 원인 가설 (최대 2개)과 각각의 근거가 되는 코드 위치
- 수정할 파일 목록
- 다른 기능에 영향을 줄 위험
- 어떻게 검증할지
```

👀 **사람이 할 일:** 원인 가설이 그럴듯한지, 수정 범위가 너무 넓지 않은지 확인합니다. 이 단계에서 방향을 잡는 것이 나중에 되돌리는 것보다 훨씬 쌉니다.

## 3단계. 실패하는 테스트 먼저 (Red)

```text
계획대로 진행해. 먼저 이 버그를 재현하는 테스트를 작성하고,
실행해서 실제로 실패하는 것을 보여줘. 아직 수정 코드는 쓰지 마.
```

> 테스트는 에이전트가 **스스로 확인할 수 있는 기준**입니다. Claude Code 공식 가이드는 에이전트에게 테스트, 스크린샷, 예상 출력처럼 스스로 확인할 수단을 주는 것을 가장 효과가 큰 방법 중 하나로 꼽습니다.

## 4단계. 구현 (Green)

```text
이제 테스트가 통과하도록 최소한으로 수정해줘.
- 테스트 코드는 수정하지 마
- 관련 테스트 전체를 다시 돌려서 기존 테스트가 깨지지 않았는지 확인해줘
```

## 5단계. 검증과 보고

```text
변경 사항을 요약해줘.
- 무엇을 왜 바꿨는지
- 실행한 테스트와 결과
- 확인하지 못한 것, 남은 위험
```

👀 **사람이 할 일:** diff를 직접 읽습니다. **읽지 않은 코드는 머지하지 않습니다.** "AI가 만든 PR을 검토 없이 올리는 것"은 Simon Willison이 꼽은 대표적인 안티패턴입니다.

## 6단계. 커밋

```text
Conventional Commits 형식으로 커밋 메시지를 제안하고 커밋해줘.
```

---

## 막혔을 때

| 증상 | 대처 |
|---|---|
| 같은 수정을 두 번 시켰는데도 실패 | 대화를 초기화(/clear)하고, 지금까지 알게 된 사실을 담아 새 프롬프트로 다시 시작 |
| 테스트를 고쳐서 통과시킴 | "테스트 코드는 수정 금지"를 명시하고, 가능하면 권한 설정이나 훅으로 막기 |
| 관련 없는 파일까지 수정 | 제약에 "수정 범위: `src/cart/` 안에서만"이라고 쓰기 |
| 대화가 길어져서 지시를 잊음 | 맥락이 썩고 있다는 신호(context rot). 요약 후 새 세션 |
