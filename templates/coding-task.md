# 코딩 에이전트 작업 지시 템플릿

> Claude Code, Codex, Gemini CLI, Cursor 같은 코딩 에이전트에 일을 맡길 때 쓰는 템플릿입니다.
> **목표 · 맥락 · 제약 · 완료 기준**의 4칸 구조는 OpenAI Codex 가이드가 권장하는 형식이고, "계획 먼저"와 "검증 수단 제공"은 Anthropic Claude Code 가이드의 핵심입니다.
> 자세한 내용은 [docs/07-ai-coding.md](../docs/07-ai-coding.md)를 참고하세요.

## 기본 템플릿

```markdown
## 목표 (Goal)
무엇을, 왜 바꾸는지 한두 문장으로.

## 맥락 (Context)
- 관련 파일/폴더: @src/auth/login.ts, @tests/auth/
- 현재 증상 (버그라면): 재현 방법, 에러 메시지 원문
- 참고할 기존 패턴: @src/auth/signup.ts 와 같은 방식으로

## 제약 (Constraints)
- 건드리지 말 것: 공개 API 시그니처, DB 스키마
- 새 라이브러리 추가 금지 (필요하면 먼저 물어볼 것)
- 기존 코드 스타일과 에러 처리 방식을 따를 것

## 완료 기준 (Done when)
- [ ] `npm test -- auth` 가 통과한다
- [ ] 재현 절차대로 했을 때 더 이상 에러가 나지 않는다
- [ ] 변경 사항 요약과 남은 위험을 보고한다
```

## 나쁜 예 → 좋은 예

| ❌ 모호한 지시 | ✅ 구체적인 지시 |
|---|---|
| 로그인 버그 고쳐줘 | 세션 만료 후 로그인하면 500 에러가 난다. `src/auth/`의 토큰 갱신 로직을 확인하고, 이 버그를 재현하는 실패 테스트를 먼저 작성한 다음 고쳐줘. |
| 테스트 추가해줘 | `utils/date.ts`의 `parseDate`에 대해 윤년, 빈 문자열, 시간대 경계 케이스 테스트를 추가해줘. 목(mock)은 쓰지 마. |
| 대시보드 만들어줘 | 매출 대시보드를 만들어줘. 기본 기능에서 그치지 말고 필터, 기간 비교, 빈 상태 화면까지 갖춘 완성도 있는 버전으로. |

## 큰 작업: 계획 먼저 받기

```text
아직 코드는 수정하지 마.
1) 관련 코드를 읽고 현재 구조를 요약해줘.
2) 변경 계획을 단계별로 제안해줘. (수정할 파일, 위험 요소, 테스트 방법 포함)
3) 내가 승인하면 그때 구현해.
```

> 대부분의 코딩 에이전트에는 **계획 모드(Plan mode)**가 있습니다. 계획 모드에서는 읽기만 하고 수정은 하지 않습니다.

## 버그 수정: 테스트 먼저 (Red → Green)

```text
1) 이 버그를 재현하는 테스트를 먼저 작성하고, 실패하는 것을 확인해줘. (Red)
2) 그다음 테스트가 통과하도록 최소한으로 수정해줘. (Green)
3) 테스트 코드는 수정하지 마.
```

## 두 번 고쳐도 안 될 때

같은 문제를 두 번 고쳐 달라고 했는데도 안 된다면, 대화를 계속 이어가지 말고 **대화를 초기화(/clear)하거나 새 세션**을 여세요. 그리고 지금까지 알게 된 사실을 반영해 더 나은 첫 프롬프트로 다시 시작하세요. Claude Code 공식 가이드가 권장하는 방법입니다.
